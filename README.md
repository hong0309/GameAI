# GameAI 

개인 프로젝트  |  FSM 과 Behavior Tree 기반 게임 AI 

## **1 프로젝트 소개** 

FSM 과 Behavior Tree 를 직접 구현하고, 동일한 적 캐릭터에서 두 의사결정 구조를 전환하며 동작을 살펴보는 프로젝트입니다. Patrol, Chase, Attack, Search 를 각 구조로 구현하여 상태 전이 방식과 우선순위 기반 행동 선택 방식의 차이를 확인할 수 있도록 구성했습니다. 

## **2 기술 스택** 

|**구분**|**사용 기술**|
|---|---|
|엔진 및 언어|Unity 6000.5.10f1 / C#|
|AI 구조|FSM 및 Behavior Tree|
|이동|Unity AI Navigation 2.0.14 / NavMeshAgent|
|감지 및 입력|거리·시야각·Raycast / Unity Input System|



## **3 주요 기능** 

### **순찰과 플레이어 감지** 

지정된 순찰 지점을 순서대로 이동합니다. 거리와 시야각을 확인하고, 장애물 레이어에 대한 Raycast 로 시야 차단 여부를 검사합니다. 감지에 성공하면 플레이어의 마지막 발견 위치를 저장합니다. 

### **추적과 공격 및 탐색** 

감지한 플레이어를 NavMeshAgent 로 추적하고 공격 범위에서 피해를 가합니다. 추적 중 시야를 잃으면 마지막 발견 위치로 이동한 뒤 정면에서 왼쪽, 오른쪽 순으로 회전하며 탐색합니다. 재발견하면 대응을 재개하고, 탐색 시간이 끝나면 순찰로 복귀합니다. 

### **실행 중 AI 모드 전환** 

숫자 키 1 과 2 로 FSM 과 Behavior Tree 를 전환합니다. 적의 위치, 순찰 인덱스, 마지막 발견 위치를 공유하여 전환 후에도 기존 상황을 이어서 판단합니다. 

### **상태 확인과 디버그 시각화** 

UI 에 현재 AI 모드와 FSM 상태 또는 BT 행동을 표시합니다. Unity 에디터의 Gizmos 로 감지 범위, 공격 범위, 시야각 경계, 순찰 경로와 마지막 발견 위치를 확인할 수 있습니다. 

## **4 핵심 설계와 구현** 

### **공통 데이터와 의사결정의 분리** 

EnemyAI 가 감지 결과, 마지막 발견 위치, 순찰 인덱스와 이동·공격 기능을 관리합니다. FSM 의 State 와 BT 의 행동 Node 는 이 공통 데이터를 참조합니다. 특히 순찰 인덱스를 EnemyAI 에서 관리하여 모드마다 순찰 진행도가 따로 바뀌는 문제를 방지했습니다. 

### **FSM** 

State 추상 클래스에 Enter, Update, Exit 를 정의하고, StateMachine 이 현재 상태와 전환을 관리합니다. 각 상태에서 다음 상태로 이동할 조건을 직접 검사합니다. 예를 들어 Chase 는 감지 실패 시 Search 로, 공격 범위 진입 시 Attack 으로 전환합니다. 

### **Behavior Tree** 

Node 의 반환값을 Success, Failure, Running 으로 구분하고 Selector, Sequence, ConditionNode 를 구현했습니다. 매 프레임 루트부터 평가하며 Selector 는 Success 또는 Running 을 반환한 자식에서 평가를 멈춥니다. Sequence 는 Failure 또는 Running 을 반환한 자식에서 멈춥니다. 

|**우선순위**|**조건**|**선택 행동**|
|---|---|---|
|1|플레이어 감지 및 공격 범위 진입|Attack|
|2|플레이어 감지|Chase|
|3|마지막 발견 위치 보유|Search|
|4|상위 분기가 행동을 선택하지 않음|Patrol|



### **마지막 발견 위치를 이용한 탐색** 

감지된 위치를 저장하여 시야 상실 후에도 탐색 목적지로 사용합니다. 도착 후에는 탐색 타이머에 따라 시작 방향 기준 왼쪽 60 도에서 오른쪽 60 도까지 회전합니다. 탐색 종료 시 마지막 위치의 유효성을 해제하여 순찰로 복귀하도록 합니다. 

### **모드 전환 시 유지되는 정보와 초기화되는 정보** 

위치, 순찰 인덱스와 마지막 발견 위치는 유지하지만 이동 경로는 초기화합니다. FSM 으로 전환할 때는 감지 여부와 공격 범위에 맞는 상태로 재진입하고, BT 로 전환할 때는 탐색 진행 상태를 초기화한 뒤 우선순위를 다시 평가합니다. 

## **5 구조 비교** 

|**비교 항목**|**FSM**|**Behavior Tree**|
|---|---|---|
|행동 결정|현재 상태의 전이 조건 검사|루트부터 조건과 우선순위<br>재평가|
|조건의 위치|각 State 내부|ConditionNode 와 트리 구성|
|행동 구성|상태별 Enter / Update / Exit|조건과 행동을 Sequence 로 조합|
|공통 정보|EnemyAI 의 감지 결과·순찰<br>인덱스·마지막 발견 위치를 공유|동일한 EnemyAI 데이터를 참조|



두 구조는 같은 네 가지 행동을 제공하지만 세부 조건과 타이머 처리까지 동일하지는 않습니다. 현재 FSM 의 Attack 은 공격 범위를 검사하고 감지 여부를 다시 검사하지 않으며, BT 의 Attack 은 감지와 공격 범위 조건을 모두 요구합니다. 또한 FSM 은 Attack 진입 시 공격 타이머를 초기화하지만 BT 는 AttackNode 의 타이머를 유지합니다.
